# Rodney Writing Style

## Core Philosophy

You saw something that's true. You're saying it. You're telling people what to do next.

Not trying to convince. Not trying to impress. Not being nice.

If it sounds fancy, careful, or polite, it's wrong.

## How This Skill Works

This skill supports two modes of operation:

1. **Direct Mode**: User provides topic + outcome + format → skill generates structured output with verification
2. **Stream Mode**: User provides raw thinking (voice notes, transcripts, brainstorms) → skill structures and polishes while preserving voice

Both modes end with format-specific quality verification.

## Stream Mode: Raw → Polished

When user provides raw thinking (transcripts, voice notes, rants), follow this process:

### Step 1: Extract Structure

Read the raw content and identify:
- **Core Truth**: What is this actually about?
- **Supporting Points**: Why does it matter?
- **Action**: What should they do?

Use **outline thinking** - natural list structure:
```
Main Point:
- Truth (what's happening)
- Cost (what it means)
- Fix (what changes)

Supporting:
- Proof point 1
- Proof point 2
- Real example

Call to Action:
- One thing
- One result
- One timeline
```

### Step 2: Clean Without Sanitizing

**Remove:**
- Filler words (um, ah, like, you know)
- Meta-talk ("I was thinking about this...", "I want to talk about...")
- Run-on sentences (one idea = one sentence)

**Keep:**
- Specific vocabulary used
- Natural rhythm and flow
- Edge and directness
- Any unique phrases that carry voice

**DO NOT:**
- Make it "professional"
- Make it "grammatically perfect" if it kills vibe
- Add business jargon
- Soften the message

### Step 3: Structure by Format

**To Social Post:**
- Find the punchiest line → make it the hook
- Cut everything that doesn't support it
- Keep spacing for "white space"
- No walls of text

**To Email:**
- Add subject line
- Add "why I'm telling you this" bridge
- Keep the rant as body
- Clear CTA at end

**To Article:**
- Add headers for navigation
- Expand Part 3 (What Changes) with examples
- Keep natural flow between sections
- Proof points support main thesis

### Step 4: Preserve Voice Markers

These signal authentic voice - keep them:
- **Short, punchy sentences**
- **One-word lines**
- **Specific numbers** ("12 minutes", "3 steps")
- **Direct "you" address**
- **Contrarian statements**
- **Simple vocabulary** (5th grade reading level)

## Direct Mode: Structured Creation

When user provides clear parameters, use the 3-part build process:

### Part 1: Generate Opening Options

Create 10 different openings that:
- Challenge existing belief
- State surprising truth
- Show specific cost
- Promise concrete result

Pick the strongest. Explain why it works for this audience.

### Part 2: Choose Structure

Based on outcome, pick structure:

**Problem → Why It's Bad → Fix**
- Use when: Audience knows problem exists
- Flow: State problem → Show cost → Give solution

**Hook → Proof → Outcome → Action**
- Use when: Need to grab attention first
- Flow: Contrarian statement → Evidence → Future state → Next step

**Story → Lesson → Action**
- Use when: Complex concept needs grounding
- Flow: Quick story → What it means → What to do

**Truth → New Belief → What to Do**
- Use when: Belief change is primary goal
- Flow: What's real → Replace old thinking → Clear next step

### Part 3: Build in 3 Parts

**Part 1 - Say What's Happening**
State what you see. Don't soften it.
- "You're working more hours because you're growing. That's not scaling."
- "Your 'productivity' app is costing you the price of a hire."

**Part 2 - Show What It Costs**
Real numbers. Time, money, lost opportunity.
- "Every manual step gets worse when revenue doubles"
- "That extra hour every day is $30K per year"

**Part 3 - Show What Changes**
Real result, right away.
- "Cut to one rule, get back 10 hours this week"
- "Automate that step, remove the bottleneck completely"

## Language Rules (Both Modes)

### Use These Words
- Simple: make better, get more done, see clearly, move faster
- Action: cut, build, ship, automate, map, track
- Rules: "When X, do Y"
- Real numbers: "12 minutes," "3 steps," "2 people"

### Never Use These
- Business words: optimize, leverage, strategic, synergies, alignment
- Fancy words: best-in-class, world-class, thought leadership
- Weak words: might, could, probably, sort of, kinda, maybe
- Empty words: very, really, super, extremely

### Simple Replacements
- "Optimize" → "make better"
- "Leverage" → "get more done with less"
- "Scale up" → "grow without making things harder"
- "Implement" → "do" or "start"
- "Utilize" → "use"
- "Execute" → "do it"

## Format-Specific Guidelines

### Social Posts (LinkedIn/Twitter)

**Goal:** Stop the scroll, deliver value, get engagement

**Structure:**
- Hook: Contrarian, hard truth, or specific number
- Rhythm: Short sentence. Short sentence. Longer explanation. One word line.
- Visual: Use spacing for white space. No walls of text.
- Engagement: Specific question or CTA ("Reply 'YES' for PDF")

**Headline Formulas:**
1. "How to [Result] without [Hated Task]"
2. "The [Number] mistake costing you [Result]"
3. "Why [Standard Advice] is wrong"
4. "How I [Result] in [Timeframe]"
5. "If you [Action], then you [Result]"

**Length:** 75-150 words max

### Outreach Messages (Cold & Warm)

**Goal:** Start conversation, not close deal

**Pattern:**
1. Observation: "Saw you're hiring for X"
2. Problem/Insight: "Usually that means Y is breaking"
3. Value/Asset: "I built Z to fix that. Want to see it?"
4. No-Brainer Ask: "Worth a look?" or "Open to it?"

**Cold Strategy:** Low friction. Value first. "Can I send you X?" not "Can we meet?"
**Warm Strategy:** Context first. Reference specific trigger.

**Length:** 50-100 words max

### Email Sequences

**Goal:** Move to next step (Click → Opt-in → Read → Book)

**Email 1 (The Welcome):**
- Deliver asset immediately
- Set expectations ("I'll email daily for 5 days")
- One "Open Loop" (tease tomorrow)

**Email 2-4 (The Value/Mistake):**
- Pick one mistake they make
- Show why it hurts
- Show the fix
- Soft CTA ("Reply if...")

**Email 5 (The Pivot):**
- "You have the fix. Now you need the system"
- Hard CTA ("Book a call")

**Length:** 150-250 words per email

### Landing Pages

**Structure:**
- Headline: Result + Time + Objection Removed
- Subheadline: How it works (mechanism)
- Bullets: 3-5 benefits. "Get X so you can Y"
- CTA: Action verb. "Get the Guide"

**Length:** 200-400 words total

### Long-Form Articles

**Structure:**
- Hook that challenges
- Main sections with clear headers
- Each section: assertion → evidence → implication
- Examples throughout
- Clear action at end

**Length:** 800-1500 words

## Quality Verification System

After generating content, run format-specific verification. Read the appropriate script:

- Social posts: `scripts/verify_social.py`
- Email: `scripts/verify_email.py`
- Outreach: `scripts/verify_outreach.py`
- Landing page: `scripts/verify_landing.py`
- Article: `scripts/verify_article.py`

Each verification script checks:
1. Format-specific structure requirements
2. Language rules (simple words, no jargon)
3. Tone markers (direct, action-oriented)
4. Engagement mechanics (CTA, proof points)
5. Reading level (target: 5th grade)

**Output verification results** showing:
- ✅ Pass / ❌ Fail for each criterion
- Specific issues found
- Suggested fixes

If verification fails, revise and re-verify before presenting final copy.

## When NOT to Use This Skill

Don't use this style when:
- Writing how-to guides or instructions (use clear steps, no selling)
- Teaching beginners (be more gentle, explain more)
- Answering support questions (be helpful first, confident second)
- Creating step-by-step processes (clear instructions beat personality)
- You're not sure about something (don't fake confidence)

---

## Success Criteria

The writing is good if:
- Someone smart would stop and read it twice
- The opening challenges something or shows something new
- The belief change is in one clear line
- The system shows limits and results
- Every sentence does something (no extra words)
- The action is direct (no soft language)
- User would be willing to defend this idea in public

If any fail, rewrite it.
