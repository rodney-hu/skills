# Bug catalog

Every real, shipped bug behind a rule in `SKILL.md`, in the order they happened. Each one is the reason a rule exists, not a hypothetical.

| # | Bug | Root cause | Rule it produced |
|---|---|---|---|
| 1 | `hover:bg-air/10`-style classes silently resolved to nothing — no error, wrong color in production | Colors authored as opaque `var(--x)` hex values; Tailwind opacity modifiers can't compose alpha onto an opaque value | 2.1 — author colors once as RGB triplets, derive everything else |
| 2 | A form-validation error message was unreadable — 2.4:1 red text on dark background, way under the 4.5:1 AA floor | Contrast never computed, only eyeballed; the base semantic color was reused as text color instead of a `-text` tint | 2.2 — dedicated `-text` variants, contrast checked by formula not eye |
| 3 | An entire elevation model (panels barely visible against the page) went unnoticed until someone actually computed composited contrast: 1.04:1 | "A bit lighter" was treated as sufficient without measuring | 2.3 — elevation tiers need measured separation, not assumed |
| 4 | A second, undocumented easing curve and multiple ad-hoc animation durations reached production, invisible to any check | JS animation (framer-motion) had no shared constant to import; every consumer hand-typed its own bezier/duration | 2.4 — export motion as JS constants alongside CSS, keep them checked against each other |
| 5 | Hardcoded border colors (`border-white/[0.18]`) sat right next to unused, purpose-built line tokens the whole time | A token existed but nothing enforced that components actually reference it instead of a literal | 3 (primitives), 4 (guard: no hand-typed literals) |
| 6 | `className="shadow-root-earth"` intended to override a card's shadow did nothing — the base component hardcoded `shadow-lg` at equal CSS specificity, and source order in the bundler's output decided the winner | A variant prop's expected override collided with a hardcoded base class at the same specificity | 3 — variants are a lookup table keyed by the prop, never "a base class plus an expected override" |
| 7 | A styling prop (`interactive`) gave a `<div>` a pointer cursor and hover lift with zero keyboard support, no focus ring, no role — an affordance that existed for a mouse and not a keyboard | Visual affordance implemented as a prop on a non-interactive element instead of a real `<a>`/`<button>` | 3 — real interactivity gets a real element (e.g. `CardLink`/`CardButton`), never a styling toggle |
| 8 | Every rule violation that ever actually shipped — 11 type sizes under 24px, 3 different `<h2>` sizes on one site, 5 competing letter-spacing values — happened in a *consuming* project; the system's own check never looked there | The guard script only ever scanned the design system's own repo | 4 — ship the checker runnable against consumer source, not just the source repo |
| 9 | A rule meant to catch a second easing curve in code started flagging the *documentation prose that described the rule itself* | The check scanned all text, not just code contexts (class attributes, CSS values) | 4 — scope checks to actual code, or they get disabled entirely |
| 10 | A design-system-only Tailwind config declared content globs for the package's own components, and downstream projects installing it still lost every class used only inside those components (a font fell back to the wrong typeface, badges lost their fill, cards lost their glow) | Assumed a preset's `content` merges with a consumer's `content` in Tailwind — it doesn't; the consumer's array replaces the preset's outright | 6 — the preset must export its globs AND every consumer must explicitly spread them in |
| 11 | The "fix" for #10 was believed to work because it typechecked and shipped — until the rebuilt CSS came back byte-for-byte identical to before the fix | Never diffed the actual build output after the change | 7 — an unchanged artifact after a fix is a bug signal, not a coincidence |
| 12 | A packaged component's kanji text rendered in the wrong (body) font — passed every static/type check, wrong in the browser | Never actually rendered the component in a real consumer, only typechecked it | 7 — typechecking is not verification; render it somewhere real |
| 13 | Verifying a font's glyph coverage via `document.fonts.check()` reported a glyph as available when the font did not actually contain it | Used an API that checks font-*face* availability, not specific glyph coverage, to answer a glyph-coverage question | 7 — verify with a cheap alternate method (rendered-width comparison) rather than trust a convenient-looking API |
| 14 | Custom `animate-*` / `transition-*` utility classes were referenced throughout a component library's source but never actually defined anywhere (no keyframes, no config entry) — they compiled to nothing, so the system's own signature "always subtly animating" behavior never ran in the shipped build | No one rendered the actual output and looked; the classes "looked right" in source | 7 — typecheck ≠ verification, same lesson as #12 from a different angle |
| 15 | A prior/sibling system was wrongly dismissed as "an unrelated naming collision, just build artifacts" during an initial search | A stale scaffold title in a `dist/` build folder was trusted over reading the actual source one directory up | 8 — verify before dismissing; don't trust an artifact's metadata over the actual files |
| 16 | A decorative background element intentionally positioned to overflow its section caused a horizontal scrollbar on every page that used it — shipped and survived three versions | The system was only ever viewed as a static local HTML file, never at a real narrow viewport in a real browser | 5 (deploy the showcase to a real URL, view narrow), 7 (verification has to include real rendering) |
| 17 | A component's entrance animation silently never played when replayed, because it was driven by `requestAnimationFrame`, which does not fire while the tab/page is backgrounded or hidden | Correctness-critical UI state depended on frame-timing rather than explicit state | 7 — prefer explicit state (counter/flag) over timer/frame-driven triggers for anything that must be correct |
| 18 | A scroll-triggered reveal left content permanently invisible (`opacity: 0`, no error) whenever the target element had zero measurable area — a collapsed container, a hidden ancestor, a headless/backgrounded viewport reporting 0×0 | An `IntersectionObserver`-gated entrance had no fallback for "the trigger can never fire" | 7 — effects gated on timers/observers need an explicit fail-open path; default to visible when the trigger can't fire |
| 19 | Two CSS classes intended to be mutually exclusive states landed on the same element at equal specificity; which one visually won depended on source order in the generated stylesheet, not on which was semantically active | Same root cause as #6, different feature (a "revealed" state class instead of a shadow variant) | 3 / 7 — specificity ties are a systemic risk, not a one-off; structure state as either/or, never both-present-hope-order-wins |
| 20 | A standalone style-guide page had its own inlined copy of the entire color palette, which fell two full versions behind the actual token source before anyone noticed | The showcase existed as a static file that couldn't literally import the real tokens, so it carried a second hand-maintained copy of every value | 5 — a showcase that can't import the real source needs its own drift guard, or needs to stop being static as soon as it can |
